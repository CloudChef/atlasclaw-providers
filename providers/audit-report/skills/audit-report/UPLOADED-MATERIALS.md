# 检测报告、检测标准及设备台账的分项目审核

本入口审核已脱敏的检测报告和用户提供的参考资料。报告、资料和规则由 LLM 作全部业务判断；本地代码只做脱敏、全文读取与解析、来源定位、结构校验、按最终问题截图及 PDF 排版。普通检测标准、设备台账及其他参考资料作为审核证据，不是规则包，也不需要编译。只有用户明确要求启用自定义规则包时，才使用规则编译流程。

## 执行命令

```text
"${ATLASCLAW_PYTHON}" "${ATLASCLAW_SKILL_DIR}/scripts/run_document_audit.py" "<待审核原始报告.pdf或.docx>" --materials "<设备台账.xlsx>" "<检测标准.xlsx>" --out "<本次独立输出目录>" --core-config "<AtlasClaw配置文件>"
```

审核使用 AtlasClaw 已配置的模型和凭据。不得把密钥写入命令行参数或输出产物。格式无效、页码/目录不完整、业务响应截断或模型调用失败时，停止发布不完整 PDF。

## 四步审核流程

### 1. 本地脱敏、提取和资料解析

- 先脱敏报告；Word 在本地转换为 PDF。只有脱敏 PDF 的内容会进入 LLM 请求。
- `report_text` 对脱敏 PDF 同时提取原生文本和保留页面布局的文本。它逐页比较两种提取结果的非空白字符计数；一致时保留布局文本以呈现列位置，不一致时该页回退到原生文本。输出用 `## Page N` 标记 PDF 物理页序，不删页或截断文字。
- 全文页数校验失败或不能完整读取全部页时停止。无法从文本可靠还原的行列关系，交由 LLM 标明证据限制；不得由本地程序补列、算数或判断。
- 本地完整解析每份上传资料并按 `M01`、`M02`……逐份编号。Excel 的解析单元格保留工作表名、物理单元格坐标/行号、原始值和可用的显示格式；原文件名、文件种类及哈希用于区分同名文件。所有完整解析正文随项目请求和汇总请求提交。
- 文件名或类型分类只说明资料用途，不代表已与报告编号、设备或日期匹配。此类比较由 LLM 逐份、逐项目完成。

### 2. LLM 识别完整项目目录

LLM 根据报告的全部原生文本识别项目编号、标题及 PDF 实际页范围。超过 32 页时，按物理页顺序逐段提交最多 32 个正式页，并带相邻页边界文本和上一段已接受的目录 JSON 作为续接线索；所有项目识别仍由 LLM 完成。本地仅校验响应格式、页码覆盖和跨段结构一致性。目录阶段不作数值、资料匹配或其他业务审核。

32 个正式页只是单次目录请求的分段大小，不是报告总页数上限；完整目录仍须覆盖全文。此分段不能突破所选模型/API 的原生上下文、生成容量或服务超时能力。若请求被模型/API拒绝、响应截断或运行超时，按实际错误停止并保留状态，不得声称完成或发布不完整报告。

### 3. LLM 逐项目审核

每个项目请求包含完整 R01–R19 规则 JSON 与说明、上传资料审核合同、全部资料完整解析正文、前置报告文本及当前项目完整脱敏原生文本。完整资料正文保留工作表和物理单元格来源位置；请求末尾的资料清单仅用于核对文件 ID、文件名和哈希，不能替代正文。

LLM 必须逐项应用内置 R01–R19 和实际启用的附加规则，逐项目核对全部适用资料、原始数据、标准条款、设备编号和日期。R10/R12 的数值及上下限比较由 LLM 根据完整文本、表头、样品、工况、行列位置和单元格来源完成；本地不按页组另发数值请求，也不计算极值、比较数值、匹配编号或判断日期。

本流程不向 LLM 提交报告页面图像或照片像素。对仅凭文本不能核实的签名、印章、照片读数、图像 AI 标记等事项，报告标注“待复核”并写明证据限制。脱敏遮挡或提取文本中未出现相关字段，不能单独证明原件确实缺失；实际原文明确支持规则所述违规条件时仍按该规则判断。

### 4. LLM 全局汇总、本地截图并生成 PDF

全局请求包含完整报告文本、全部解析资料、完整 R01–R19 规则及说明、每个项目的完整原始 Markdown 和汇总合同。LLM 负责全局覆盖表、资料矩阵、跨项目关系、问题与总评；不得由本地程序合并、计算或改写业务结论。覆盖表对文本证据不足的规则使用“待复核”，并保留具体原因；不能把限制改成无保留通过或原件缺陷。

LLM 完成审核后，本地根据每条问题引用的实际 PDF 页码生成局部截图，并将完整全局报告和项目原文排版为审核 PDF。截图只用于定位报告中已由 LLM 作出的文字判断，不表示模型查看过截图。HTML 仅是本地中间预览，最终交付物为 PDF。输出结构、页码、规则 ID/等级等格式检查失败时，不得通过本地改写业务内容来发布。

## 输出和追溯产物

- `desensitized.pdf`、`preparation.json`：脱敏报告和准备记录。
- `submission.json`、`materials-used.json`：页数、字符数、规则 ID 和资料文件清单/哈希；不含凭据。
- `index-raw.txt`，或 `index-chunks/` 下的分段原始响应及 `workflow.json`：目录模型原稿和结构校验记录。
- `projects/NNN-raw.md`、重试原稿及 `audit-main-raw.md`：逐项目和全局模型原始 Markdown。
- `audit-raw.md`、`audit.md`：完整拼接原稿与供本地交付检查的 Markdown。
- `evidence/`、`audit-report.html`、`audit-report.pdf`、`delivery.json`：问题截图、中间预览、最终 PDF 和交付记录。
- CLI 另保存 `model-usage.json`；所有原始模型响应、提示词哈希/调用记录及工作流状态按实际目录清单留存。

实际文件名以本次工作目录和 `workflow.json` 为准。调用失败、截断、目录缺页或必要响应结构无效时保留已有原稿和状态，但不得发布不完整审核 PDF；不得本地补写或猜测缺失的业务结论。

## 补充资料边界

若检测标准仅提供目录、名称或编号而没有适用条文正文，LLM 只能核对本次实际提供的信息，不能虚构标准要求、限值或合格条件；缺少必要依据时标明证据限制。R14 设备使用有效期与 R15 校准有效期须分别判断，台账字段一致性也须单独报告。仅有截止日期不能证明完整历史校准有效期间。

`extract_report.py` 仍保留按显式选项导出页面图片的本地工具能力；此选项不属于本审核入口的模型输入流程。本入口始终按上述文本流程执行。
