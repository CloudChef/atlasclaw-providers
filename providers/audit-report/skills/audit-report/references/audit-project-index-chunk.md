# 分段项目目录扫描合同

只分析本次提交的正式页范围，定位报告内项目段。不得对设备、数据、标准或规则作业务审核，不输出审核结论。

- 必须逐页阅读全部正式页原生文本，并结合页标题、章节文本、表格和提取到的图注/附件文字判断分段；不得因分段长度或预期项目数量而拆分/合并。
- 目录、结论汇总表、前置测试参数表等全局内容中提到的项目编号只是引用，不表示该项目正文从该页开始。只有全局内容的页应列入 `non_project_pages`；从实际项目内容起始页确定项目范围。
- `segments` 只包含检测项目及其对应的结果、续表和文字标注的附件；封面、目录、报告声明、签发记录、修订记录等非检测章节逐页列入 `non_project_pages`，并保留给后续全局审核，不得列作项目段。
- 新项目必须从报告正文中可核实的项目标题/正文起点开始，不能把目录或汇总内容中的引用当作正文起点。上一项目正文开始后、下一项目实际正文标题之前可依据内容关联到上一项目的附图、曲线、续表及附件，不能仅因接近下一标题就转归新项目；不能只覆盖可提取文字的页面。
- 项目内部或末尾的空白/低文字页不自动终止项目。结合前后正文、表格连续性、提取到的图注和附件文字判断归属；存在疑点时保留页面归属证据供后续 R01 审核，不可仅因页面文字为空就判为非项目页。
- `reviewed_pages` 是可省略的历史兼容元数据，不要求输出。若出现，不可信为正式页覆盖证明，也不替代下方 `segments` 与 `non_project_pages` 的页范围分类。相邻页上下文包括前一和/或后一物理页，仅用于理解分段边界，不得纳入正式页覆盖或项目页范围。
- `segments` 和 `non_project_pages` 可省略；省略时按空数组处理，但无论是否省略，都必须由两者所列页范围共同完整覆盖本段全部正式页，不能遗漏或重复冲突分类。若提供 `segments`，每项必须包含非空字符串 `id`、非空字符串 `title`、整数 `page_start` 和整数 `page_end`。当某项目 ID 首次出现在已扫描范围时，必须给出 `start_quote`，作为其正文起点锚点；只有当该 ID 已出现在上一段扫描记录中、且本段是该项目续接时，`start_quote` 才可为空或省略，并沿用前段已确证的项目 ID。新项目的 `start_quote` 必须是可在其 `page_start` 对应正式页原生文字中核实的标题/起点原文；校验时允许忽略全部空白字符差异，但任何非空白字符、标点或数字都必须一致。不得引用相邻页或其他页。可选的 `start_evidence`/`end_evidence` 可补充说明边界依据，但不替代必需字段或原文锚点。
- 使用报告可读的原始项目编号；无编号时，由你为同一项目跨段分配稳定一致的描述性 ID。若不同独立项目使用相同可读编号，使用不同且稳定的 ID 区分。若有上一段扫描记录，续接项目必须沿用其中已出现的 ID 和 title；所有页面关系及项目范围由你依据正式页证据识别。
- 同一物理页可以同时属于两个相邻项目；不同项目段的范围可以在共享边界页重叠。每个正式页必须至少被一个项目段覆盖，或在 `non_project_pages` 中逐页说明；非项目页不能同时落入任何项目段。不得把上下文页计入覆盖。
- `non_project_pages` 可省略，省略时按空数组处理；若提供，必须是对象数组，每项包含正式页整数 `page` 与非空字符串 `reason`，说明该页为何不是项目内容。不得用连续文字跳过正式页。
- `start_status`/`end_status` 等状态字段不是必需项；若返回，只作为非权威提示，不能代替项目 ID、页码范围或新项目起点原文，也不能作为合并或验收条件。
- 分段请求按页顺序执行；仅当存在上一段时才提供其已校验的 JSON 原文作为续接线索。上一段 JSON 与相邻页上下文都不是本段正式页证据，项目范围仍须由当前正式页内容决定。不要把分段边界误判为自然项目结束。

只返回以下结构的JSON对象，不加解释或Markdown围栏：

```json
{"segments":[{"id":"项目编号或稳定ID","title":"项目名","page_start":1,"page_end":2,"start_quote":"正文标题的原文引用"}]}
```
