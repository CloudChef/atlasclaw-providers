# 问题核验（Finding Verification）

每条“不通过”都由 LLM 依据本次提供的脱敏文本和解析资料完成语义核验；本地脚本只检查结构、页码、引文定位和截图文件，不作业务判断。文本证据不足时，不能写成通过，也不能把脱敏/提取限制判作原件缺陷。

## 第一层：脚本核验

```bash
python scripts/verify_findings.py "<audit-report.md>" \
  --source "<提取目录>" \
  --evidence "<evidence 目录>" \
  --out verification.md --json verification.json
```

脚本检查：

| 检查 | 失败后果 |
| --- | --- |
| 页码在源文档范围内 | FAIL |
| 至少一条引文出现在报告页码的文本层 | FAIL / REVIEW |
| 截图文件存在、可读、非空 | FAIL |
| 截图 sidecar 页码与报告页码一致 | FAIL |
| 规则号属于 R01–R19 | FAIL |
| 等级与规则固定等级一致 | FAIL |
| 覆盖表该规则为“不通过” | FAIL |
| 引文未命中或无法从文本核实 | REVIEW |

- **FAIL**：必须修正或删除该问题，不能交付。
- **REVIEW**：证据不足或定位待复核；不能写成“已核验”，也不能据此推断原件缺失。
- **PASS**：只代表文本层可核对，仍需第二层语义核验。

## 第二层：语义核验

逐条回答以下问题，全部为“是”才可保留：

1. **引文真实**：引文确实在报告该页/该章节，不是模型改写、拼接或编造。
2. **规则命中**：引文满足该规则的不通过条件，而不只是“看起来有问题”。
3. **等级正确**：A/B/C 与规则表一致，没有为了“看起来轻一点”降级。
4. **不是误报**：
   - 不是脱敏后的 `N/A` 被当成原始数据；
   - 不是 OCR/扫描识别错误；
   - 不是中英文翻译差异；
   - 不是把“要求”当成“实测值”；
   - 不是把“不适用”当成“不合格”。
5. **数值/日期已核对**：由 LLM 对照原始文本、表格位置、适用限值和日期证据逐项判断；本地代码不计算业务结果。
6. **去重**：同一位置、同一原因不重复列条；同一证据触发多条规则时标注关联。
7. **文本证据边界**：本流程未提交页面图像；签名、印章、骑缝、照片或 AI 水印无法从文本确认时，标为“证据不足/无法核验”，不能伪称已查看或判原件缺陷。

## 19 项语义核对要点

| 规则 | 必须确认 |
| --- | --- |
| R01 | 页码确实断号/缺页/乱码，不是空白页或正常分页 |
| R02 | 三个签署角色确实缺失/同一人；不是仅缺日期就误判为“全缺” |
| R03 | 专用章/骑缝章确实缺失；电子章需确认可见性 |
| R04 | 同批文件齐全，主编号后缀确实不一致 |
| R05 | 同一报告内确实出现两个不同编号，不是页眉/正文正常引用 |
| R06 | 报告编号 7 位与样品编号前 7 位逐位比对不一致 |
| R07 | 同一标准年代号确实不一致或缺年份 |
| R08 | 方法温度/电压与照片显示值确实不一致，不是照片没拍到 |
| R09 | 要求项数确实多于数据行数，不是合并单元格/跨页误数 |
| R10 | max > 上限或 min < 下限，等值不算超限 |
| R11 | 汇总表“结果评判”与正文同一项目结论确实不同 |
| R12 | 确有未达标数据仍判合格，不是把“合格”当数据 |
| R13 | 日期链确实逆序，不是日期格式/时区误读 |
| R14 | 检测日期确实超出设备使用有效期 |
| R15 | 检测日期确实超出校准有效期；无设备清单按证据不足判不合格 |
| R16 | 分包声明确实非“无”且未注明实验室名称 |
| R17 | 错别字/病句/编号错乱确实存在，不是专业术语误判 |
| R18 | 英文拼写/语法错误确实存在，不是标准英文名/缩写 |
| R19 | 照片确有 AI 水印/生成痕迹，不是压缩噪点/屏幕摩尔纹 |

## 常见误报

| 误报 | 处理 |
| --- | --- |
| 把脱敏后的 `N/A` 当成原始值 | 删除该问题；脱敏值不能作为审核证据 |
| 引文只在其他页出现 | 核对页码；页码错则改页码，引文不存在则删除 |
| 把“要求 ≤80”当成“实测 80” | 重新读取数据表，区分要求列和实测列 |
| 把“未拍到”当成“不一致” | 证据不足按不合格处理，但说明是“缺少证据”而非“数值不一致” |
| 把“合格/Pass”当成数据达标 | 逐项复算后再判 R12 |
| 把标准英文名/商标当拼写错误 | 删除 R18 误报 |
| 把空白页当缺页 | 核对页码和“此页无正文”标注 |
| 把同一证据重复计为多条 | 合并或标注关联，统计时说明 |

## 跨页核验

- 表头在上一页、数据行在下一页时，必须合并两页判定；不能因为单页看不到就判“缺失”。
- 引文出现在相邻页（默认 ±1 页）时，视为跨页证据，但报告页码要写“第 X–Y 页”。
- 引文只在不相邻的页出现时，先核对页码；页码错则改页码，引文不存在则删除。
- 跨页问题截图应包含两页，至少包含问题点所在页；sidecar 记录的主页码必须在报告页码中。

## 文本证据限制

- 本次模型输入只有脱敏文本与解析资料，没有页面图像或照片像素。对无法由文本核实的视觉事项写明证据限制，不称截图已附或已查看。
- 若脱敏遮挡或提取缺失，不能据此判定原报告缺少签字、印章、照片或字段；只有可核实原文明确支持时才按规则判断。
- 最终 PDF 的问题截图由本地根据已确认的问题位置生成，不代表本轮模型检查过截图内容。

## 核验状态写法

报告“审核对象”表增加一行：

```markdown
| 核验状态 | 文本证据充分 `<n>` 条；证据不足/无法核验 `<m>` 条；不通过 `<k>` 条 |
```

- 有 FAIL：不得交付。
- 有 REVIEW：可以交付，但必须明确具体文本证据限制，不能写“已全部核验”。
- 全部 PASS 且语义复核通过：写“已逐条核验”。
