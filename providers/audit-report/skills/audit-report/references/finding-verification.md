# 问题核验（Finding Verification）

每条“不通过”都由 LLM 依据本次提供的脱敏文本和解析资料完成语义核验；本地脚本只检查结构、页码、引文定位和截图文件，不作业务判断。文本证据不足时，不能写成通过，也不能把脱敏/提取限制判作原件缺陷。

## 第一层：脚本核验

```bash
python scripts/verify_findings.py "<audit-report.md>" \
  --source "<提取目录>" \
  --evidence "<evidence 目录>" \
  --out verification.md --json verification.json
```

脚本检查：

| 检查 | 失败后果 |
| --- | --- |
| 页码在源文档范围内 | FAIL |
| 至少一条引文出现在报告页码的文本层 | FAIL / REVIEW |
| 截图文件存在、可读、非空 | FAIL |
| 截图 sidecar 页码与报告页码一致 | FAIL |
| 规则号属于已启用规则集 | FAIL |
| 等级与规则固定等级一致 | FAIL |
| 覆盖表该规则为“不通过” | FAIL |
| 引文未命中或无法从文本核实 | REVIEW |

- **FAIL**：必须修正或删除该问题，不能交付。
- **REVIEW**：证据不足或定位待复核；不能写成“已核验”，也不能据此推断原件缺失。
- **PASS**：只代表文本层可核对，仍需第二层语义核验。

## 第二层：语义核验

逐条回答以下问题，全部为“是”才可保留：

1. **引文真实**：引文确实在报告该页/该章节，不是模型改写、拼接或编造。
2. **规则命中**：引文满足该规则的不通过条件，而不只是“看起来有问题”。
3. **等级正确**：A/B/C 与规则表一致，没有为了“看起来轻一点”降级。
4. **不是误报**：
   - 不是脱敏后的 `N/A` 被当成原始数据；
   - 不是 OCR/扫描识别错误；
   - 不是中英文翻译差异；
   - 不是把“要求”当成“实测值”；
   - 不是把“不适用”当成“不合格”。
5. **数值/日期已核对**：由 LLM 对照原始文本、表格位置、适用限值和日期证据逐项判断；本地代码不计算业务结果。
6. **去重**：同一位置、同一原因不重复列条；同一证据触发多条规则时标注关联。
7. **视觉证据边界**：页面图像由独立视觉模型核查，记录以 Mxx 资料提交；引用视觉记录时必须带页码/区域，无法辨认时标“待复核”，不能伪称已查看或判原件缺陷。

## 规则语义核对要点

对每条问题，确认引文/图像证据确实满足该规则 JSON 的 `fail_when`，而不是只“看起来有问题”。

| 规则 | 检查项 | 必须确认的不通过条件 |
| --- | --- | --- |
| R01 | 页码连续完整 | 页码不连续，页码不完整，页眉或页脚处的当前页码/总页码与实际情况不一致。 |
| R02 | “目录”部分各标题所在页码与正文中实际的页码保持一致 | “目录”部分各标题所在页码与正文中实际的页码不一致 |
| R03 | 报告编号唯一性 | 同一份报告中页眉、正文各部分报告编号不一致，如出现字母代号不一致，报告编号字符数不一致，内容不一致等 |
| R04 | 样品编号与报告编号的相关性 | 样品编号前7位数字与报告编号前7位数字不一致 |
| R05 | 单项测试中检测结果部分的样品编号与检测照片下标的样品编号一致性 | 单项测试中检测结果部分的样品编号与检测照片下标的样品编号不一致，照片中拍到的样品编号与下方备注的样品编号信息不一致 |
| R06 | 登记的样品数量与样品编号所述一致 | 样品编号显示的样品个数 = 样品数量（赛力斯报告有样品数量汇总要求项） |
| R07 | 检测标准与标准库登记的内容不一致 | 查询标准库，检测标准不是最新版；检测标准字符数与标准库中登记的字符数不一致，如缺少尾标①，多或少字符、缺少"/",":"或"-"等符号或符号位置不对。 |
| R08 | 检测标准的一致性 | 相同检测标准在正文不同位置写法不一致，如缺少年代号，字符数量不一致 |
| R09 | 日期的逻辑性 | 报告中日期有笔误，如2026年的检测，误写成2024，2027等明显的错误 |
| R10 | 日期的逻辑性 | 日期规则：生产日期（批次号）≤包装日期≤送样日期≤到样日期≤预处理日期≤检测日期≤分析日期≤报告日期≤报告签发日期 |
| R11 | 日期的有效性 | 气味、雾化、总碳、袋子法、甲醛、VOC等散发类测试中，样品检测完成日期-样品生产日期大于15天 |
| R12 | 日期冲突 | 顺序试验中，相同测试序列中的各项试验的检测日期出现了一天以上的重合 |
| R13 | 时间的有效性 | 检测日期段的总时长＜检测方法描述中的要求时长。如稳态湿热要求测试21天，报告中检测日期2026.11.01~2026.11.20，实际区间只有20天，且无任何偏离说明。 |
| R14 | 照片中时间戳的一致性和有效性 | 单项试验中，检测照片中时间戳水印的日期位于检测检测日期范围外； |
| R15 | 照片中时间戳与时钟所示时间的一致性 | 同一张检测照片中时间戳水印的时间与照片中时钟所示的时间差异超过2分钟 |
| R16 | 检测照片中环境箱的时间的有效性 | 检测照片中设备面板上显示的日期位于检测日期范围外 |
| R17 | 目录与实际标题的一致性 | 目录章节信息和页码与正文中实际章节和所在页码不一致，目录信息未更新 |
| R18 | 章节号验证 | 章节序号不符合顺延逻辑，有跳号现象 |
| R19 | 设备信息与设备台账的一致性 | 报告中设备名称（或英文设备名称）、编号、型号规格、校准有效期与提供的设备台账信息一致，外来设备不进行查询 |
| R20 | 外来设备信息的一致性 | 当前报告中使用的外来设备名称、编号等相同的信息，在报告不同页面中由于笔误填写的不一致 |
| R21 | 设备校准有效期核查 | 单项测试中的设备校准有效期不能覆盖到检测日期范围，如检测日期为2026-11-01~2026-11-20，设备校准有效期为2026-11-10 |
| R22 | 设备信息的重复性检查 | 不同测试序列的检测项目，在有重合的检测日期时段内使用了相同编号的设备，如环境箱、振动台、电源、数采等设备 |
| R23 | 设备遗漏 | 检测方法和检测结果描述需要用到的设备，在检测设备栏里的填写有遗漏，只有主要设备，遗漏了如测量pH、电导率、盐度、尺寸、重量、温度、风速等专用的仪器设备。 |
| R24 | 结果分包声明验证 | 如“结果分包声明”为“无”，则全文不应出现分包方名称，如有分包方名称，则分包声明不可以为“无” |
| R25 | 认可状态声明 | 如报告中有分包方名称，则不可以出现“报告中所有项目均在OEM认可范围内”的声明文字。 |
| R26 | 结果单位验证 | 常用单位书写不规范，特别是大小写，比如压力单位kPa，k应小写P应大写，扭矩单位N·m不规范写成Nm，℃写成°C等 |
| R27 | 中文语法验证 | 中文有乱码，错别字，语句不通顺，无效空格，字体不一致，同一段落内容重复等 |
| R28 | 英文语法验证 | 英文有乱码，单词拼写错误，语法错误，语句不通顺，无效空格，字体不一致，同一段落内容重复等 |
| R29 | 中英文内容对照验证 | 中英文内容冲突，内容翻译后有明显差异 |
| R30 | 照片比例 | 检测照片部分长宽比例不一致，照片大小差异明显 |
| R31 | 照片AI生成核查 | 照片中有“AI生成”水印痕迹残留，或明显的AI生成特征 |
| R32 | 照片复用/误用 | 同一份报告中不同位置出现了完全相同的复用照片，或者外观、颜色差异较大的误用照片 |
| R33 | 照片内容与测试条件的符合性 | 检测方法描述要求的温度、电压等测试条件与检测照片内容呈现的不一致，如测试方法要求23℃，检测照片放置的是80℃ |
| R34 | 曲线时间的有效性 | 生成的曲线时间轴上的时段未包含在检测日期范围内，或测试条件要求168h的时长，生成的曲线上时间段不足168h |
| R35 | 相同信息一致性核查 | 报告中重复出现的内容信息需一致，如实验室名称、地址、零件名称、零件号、试验项目名称等 |
| R36 | 温度、湿度范围符合性检查 | 正文中检测环境的温度和湿度结果超过了方法描述中的温度和湿度环境限值要求，如要求在23±2℃，50±5%RH 下进行，检测环境写成了25.2℃或湿度写成了49% RH. |
| R37 | 温度、湿度内容符合性检查 | “检测环境”栏内容填写不符合规则要求。规则为：温度：填写到小数点后一位，湿度结果取整。 |
| R38 | 结果评价验证 | 目录部分的结果评价与正文对应检测项目的结果评价不一致：目录为合格/pass，正文部分对应试验项目的所有样品的检测结果出现了一个结果判定为不合格/fail/不判定；目录为FAIL/不合格，正文部分对应试验项目的所有样品的检测结果判定均为pass/合格/不判定；目录中的结论为不判定,正文部分对应试验项目的所有样品的检测结果出现了一个合格/不合格的判定描述。 |
| R39 | 结果单位验证 | 检测结果缺少单位信息，如电流、电压、电阻、尺寸、电导率、功率、温度、湿度、流量等结果描述部分只有数字，无单位 |
| R40 | 结果验证 | 相同检测项目的样品间结果差异过大，如小数点点错位置，数值修约的小数位数不一致，结果单位不一致 |
| R41 | 结论与数据逻辑性验证 | 存在未达标数据仍判"合格"，合格数据判定为“不合格”或不评判 |
| R42 | 数据计算结果验证 | 平均值、最大值、最小值、中值、百分比、变化率、差值（试验后-试验前）计算错误 |
| R43 | 数据计算结果验证 | 色差计算错误 |
| R44 | 结果判定验证 | 检测结果极限值代入验证后判定结论错误：最大值 > 上限要求，或最小值 < 下限要求（实测值超出规定区间） |
| R45 | 结果的完整性验证 | 如评判要求 5 项而检测结果少于 5 项（要求项数 ≠ 数据表行数 |
| R46 | 多份文档交叉验证 | 同时上传的试验大纲、测试计划、原始记录、委托单等文档中的信息与检测报告相关内容进行交叉比对，核对信息的一致性：检测方法描述是否一致，评判要求是否一致，样品信息是否一致，客户信息是否一致等 |

## 常见误报

| 误报 | 处理 |
| --- | --- |
| 把脱敏后的 `N/A` 当成原始值 | 删除该问题；脱敏值不能作为审核证据 |
| 引文只在其他页出现 | 核对页码；页码错则改页码，引文不存在则删除 |
| 把“要求 ≤80”当成“实测 80” | 重新读取数据表，区分要求列和实测列 |
| 把“未拍到”当成“不一致” | 证据不足按不合格处理，但说明是“缺少证据”而非“数值不一致” |
| 把“合格/Pass”当成数据达标 | 逐项复算后再判 R41 |
| 把标准英文名/商标当拼写错误 | 删除 R28 误报 |
| 把空白页当缺页 | 核对页码和“此页无正文”标注 |
| 把同一证据重复计为多条 | 合并或标注关联，统计时说明 |

## 跨页核验

- 表头在上一页、数据行在下一页时，必须合并两页判定；不能因为单页看不到就判“缺失”。
- 引文出现在相邻页（默认 ±1 页）时，视为跨页证据，但报告页码要写“第 X–Y 页”。
- 引文只在不相邻的页出现时，先核对页码；页码错则改页码，引文不存在则删除。
- 跨页问题截图应包含两页，至少包含问题点所在页；sidecar 记录的主页码必须在报告页码中。

## 文本证据限制

- 本地核验脚本只读取脱敏文本、解析资料和截图文件，不会提交图像给模型。视觉事项应引用审核流程的 Mxx 视觉核查记录；没有该记录时写明证据限制，不称本脚本已查看图像。
- 若脱敏遮挡或提取缺失，不能据此判定原报告缺少签字、印章、照片或字段；视觉模型只依据原始页面图像中实际可见内容观察。
- 最终 PDF 的问题截图由本地根据已确认的问题位置生成，不代表本轮模型检查过截图内容。

## 核验状态写法

报告“审核对象”表增加一行：

```markdown
| 核验状态 | 文本证据充分 `<n>` 条；证据不足/无法核验 `<m>` 条；不通过 `<k>` 条 |
```

- 有 FAIL：不得交付。
- 有 REVIEW：可以交付，但必须明确具体文本证据限制，不能写“已全部核验”。
- 全部 PASS 且语义复核通过：写“已逐条核验”。
