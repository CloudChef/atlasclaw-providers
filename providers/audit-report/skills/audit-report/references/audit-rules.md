# 19 项审核规则详解

本文件是 `audit-report` 的内置 19 项执行细则。审核时逐条检查；`rules/builtin/rules.json` 是规则条件与等级的唯一事实源，本文件不得扩展或改写 JSON 的 `fail_when` / `severity`。说明与 JSON 冲突时以 JSON 为准。

附加规则不在本文件：规则文档放在 `rules/_inbox/`，编译为 `rules/packs/<包名>/pack.json` 后按包内 `fail_when` 执行；流程见 `rules/README.md`。内置规则的执行事实源是 `rules/builtin/rules.json`，说明文档应忠实转述该 JSON，不得扩展 JSON 条件或等级。

**本流程证据边界**：本次只向 LLM 提交脱敏文本与本地解析资料，不提交页面图像/照片。R02/R03/R08/R19 的规则条件不变，但若签名、印章、照片或 AI 标记仅能从未提交的图像确认，覆盖表标“待复核”并说明文本证据限制。提取文本未出现姓名、印章或照片信息，不等于原件确实缺少；只有本次文本直接支持规则所述违规时才判不通过。不得声称看图或把无法核验写成通过/原件缺陷。

## 通用取证约定

| 项目 | 要求 |
| --- | --- |
| 页码 | 以 PDF 实际物理页序为准；印刷页码仅作辅助并列，不替代物理页码。Word 文件按实际渲染后的 PDF 物理页序定位。 |
| 定位 | 报告不写内部行号；用“PDF物理页码 + 章节/条款号 + 足以辨认问题的原文上下文”定位；上下文按原文实际形式引用，不要求句数；表格或字段按行列/字段定位，不臆造句子；表格用“表 N 第 R 行”；图像注明区域（签章区/照片区）；整份缺失写“全文”并列出可核查范围 |
| 跨页 | 表头/数据行/结论跨页时合并前后页判定；页码写“第 X–Y 页”；不得因单页看不到就判缺失 |
| 原文 | 原样抄录，保留完整上下文及空格、大小写、连字符、全半角；不设引用长度上限 |
| 图像 | 本流程仅提交文本与解析资料；未提交图像时不得描述其可见内容。说明“证据不足/无法核验”，且不能据此断言原件缺失 |
| 缺失 | 只有本次可核实的原文证据支持“报告未载明”时，才按对应规则判定；脱敏/提取未显示不等于原件未载明 |
| 等级 | A 严重、B 主要、C 次要；严格按表，不因整改成本低而降级 |
| 去重 | 同一证据触发多条规则时分别记录，标注"关联问题" |

**输出完整性**：每个不符合项单独成条；同一规则在不同位置的多处违规必须分别列条，不得合并或用"等"省略。每条必须带页码、位置、原文上下文、证据和不规范说明；本地流程按已确认的问题位置附页面局部截图。

## 问题拆分口径

| 规则 | 一条问题的粒度 |
| --- | --- |
| R01 | 每个缺页/乱码页一条 |
| R02 | 缺失的每个签署角色一条；三人同一人一条；整块无签署栏一条 |
| R03 | 专用章、骑缝章分别一条；整份无印章按两个子项各一条 |
| R04 | 每个不一致的主编号一条（列出文件） |
| R05 | 每个冲突编号值一条（列出所有出现位置） |
| R06 | 每个不一致的样品编号一条 |
| R07 | 每个标准（年份写法不一致/缺年份）一条 |
| R08 | 每个项目/每张照片的条件不一致一条 |
| R09 | 每个缺失的要求项一条；数量不一致在说明中汇总 |
| R10 | 每个越界数据行一条（同一行多个越界值可一条） |
| R11 | 每个结论冲突的项目一条 |
| R12 | 每个错误判定单元格一条；综合结论错误另加一条 |
| R13 | 每个断裂的日期链环节一条 |
| R14/R15 | 每台设备/每个项目日期越界一条 |
| R16 | 每个分包声明缺陷一条 |
| R17 | 每个不同错字/病句一条；同一错字多处合并并列出全部位置 |
| R18 | 每个英文错误一条 |
| R19 | 每张有 AI 标记/痕迹的照片一条 |

原则：不同位置、不同数据行、不同结论分别列条；同一位置同一原因不重复；整份缺失可用一条并把“全文”写入位置。

严重等级定义（仅用于成立问题；统计只计成立问题）：

- **A · 严重**：影响报告有效性、编号唯一性或数据可信度；必须整改后重新审核。
- **B · 主要**：合规性、一致性或证据链缺陷；整改后复核。
- **C · 次要**：文字质量问题；仍需修订，整改优先级最低。

### 结果取值

证据缺失、脱敏遮挡、不可读或无法核对本身不是 JSON 定义的违规条件；应标“待复核”并说明证据限制，不能仅据此判不通过。只有 JSON 条件明确规定相应缺失本身构成失败时，才能将该缺失判不通过。

| 结果 | 使用条件 |
| --- | --- |
| 通过 | 已取得充分证据，且满足规则 |
| 不通过（不合格） | 已取得证据证明违反该规则 JSON 的 `fail_when` 条件；必须写明违规点和可核对证据 |
| 不适用 | 规则前提在报告中根本不存在且不构成缺陷（如全篇无照片时的 R19、无英文内容时的 R18） |

### 不可读页面的处理

- 遇到不可读/缺失页且无法判断其是否包含相关信息时标“待复核”；只有已核实存在缺页或乱码，或其他原文证据满足对应 JSON 条件时，才判不通过。
- 空白页、已确认不含编号的附件页，可在注明证据范围后判通过。
- 局部规则只在有充分证据支持 JSON 条件时判通过或不通过；无法核验时标“待复核”。JSON 明确规定整块缺失构成失败的规则，才按该条件判不通过。

## R01 页码连续完整（B · 主要）

**不通过条件**：存在缺页、乱码。

**取证位置**：每页页脚/页眉的页码与总页数、PDF 物理页序、扫描页、附件页。

**判定步骤**：

1. 记录 PDF 实际物理页数，并将报告印刷页码作为辅助信息核对；定位始终使用 PDF 物理页序。
2. 先确认是否存在**规范页码**（页眉/页脚中的"第 X 页 共 Y 页"或卷内连续编号）。标题内嵌的 `Page 1`、文件名页码不算规范页码，只作补充观察，不能据此证明连续性。
3. 从头到尾检查页码是否连续：跳号、重号、空号、总页数前后不一致。
4. 检查首页、末页、附件、骑缝页是否缺失；正文提到的"见附件 X"是否实际存在。
5. 通读每页文本，标记乱码：`锟斤拷`、`口口口`、大量 `?`、异常符号、编码错位、整段空白。
6. 扫描页模糊但文字可辨，不算乱码；整页无法辨认、但不能确认是乱码时标“待复核”，不得仅因不可读判 R01 不通过。

**通过**：页码连续、总页数一致、无乱码、引用附件齐全。

**不通过示例**：

- 第 5 页后直接第 7 页，缺第 6 页；
- 页脚"共 10 页"，实际 9 页；
- 第 4 页检测数据表格显示为乱码或方块。

**易错点**：

- 封面、封底无页码不等于缺页；只要正文页码自身连续即可。
- 附件单独编号（附 1-1、附 1-2）不算缺页，但要检查附件内部连续。
- 空白页若在页码序列内可接受；若导致正文缺页则判不通过。
- 全篇没有规范页码、又存在空白/不可读页时，连续性无法证明，标“待复核”；明确断号、缺页、乱码才按 R01 判不通过。
- Word 包内未被引用的页眉/页脚（`referenced=false`）不会渲染，不能作为页码证据。
- PDF 加密/权限受限导致无法提取文本，不等于乱码；先渲染页面确认。

## R02 三方签章（编制/审核/批准）（A · 严重）

**不通过条件**：签署不齐全，或编制、审核、批准为同一人。

**取证位置**：封面、报告签署页、批准页、结论页、原始记录签字栏。

**判定步骤**：

1. 定位三个签署栏：编制、审核、批准（有的报告写作"编写/审核/批准"或"检测/审核/批准"）。
2. 逐栏核对编制、审核、批准的实际签署证据；不另加 JSON 未规定的独立签署日期必填条件。共同签发日期与个人签署日期须区分。
3. 核对可用的姓名及身份/签署证据。姓名相同只构成身份核实线索；不能仅凭同名就证明为同一人。
4. 检查是否存在代签、打印姓名冒充签名、空白栏、"（签字）"占位。
5. 电子签章报告：确认电子签名可见且与签署人对应；仅有图片印章不算三方签名。
6. 整份报告没有签署栏、签署页或任何签署人姓名：经逐页确认后视为"签署不齐全"，判不通过（A），不要判"不适用"。

**通过**：有充分证据核实三方签署齐全，且不存在 JSON 所述同一人签署情形。

**不通过示例**：

- 批准栏空白；
- 编制与审核均为"张三"；
- 三栏都打印"李四"且无手写签名；
- 签署页只有公章，没有三个人名。

**易错点**：

- 不凭字迹或相同姓名直接认定同一人；身份无法确认时标待复核。
- "张三"与"张叁"不直接判同一人，标注"姓名形近，待核实"。
- 不因未逐人单列日期就判签署不齐全；仅按 JSON 条件和可确认的签署证据判断。
- 报告有多个签署页（分报告、附件）时，每处都要查。
- "没有签署栏"不是"不适用"：整块缺失本身就是签署不齐全，只要有完整页面证据即可判 A。
- 只有打印姓名、没有手写签名或可验证电子签名 → 签署不齐全（A）。

## R03 报告专用章/骑缝章（B · 主要）

**不通过条件**：未加盖专用章或骑缝章。

**取证位置**：报告结论/声明盖章页、每页装订边或页面边缘、附件骑缝处。

**判定步骤**：

1. 确认报告专用章：章面应含机构名称及"报告专用章"/"检验检测专用章"等字样，位置通常在结论页或封面。
2. 确认骑缝章：多页报告装订边每页应有同一印章的残片，能跨页拼合；检查首末页和中间随机页。
3. 电子报告：检查电子印章是否可见、是否覆盖关键页；电子骑缝章按其呈现形式核对。
4. 单页报告：骑缝章子项记"不适用"，R03 总体结果仍按专用章检查结果判定。
5. 整份报告没有任何印章图像、矢量图形或扫描痕迹：经逐页确认后判不通过（B）；多页报告缺骑缝章同样判不通过，不要判"不适用"。

**通过**：专用章齐全；多页报告骑缝章跨页完整。

**不通过示例**：

- 只有公章，无"报告专用章"；
- 专用章缺失；
- 多页报告仅首页盖章，装订边无骑缝章残片；
- 骑缝章只覆盖前两页，后续页无章。

**易错点**：

- 黑白复印件上的章可能很淡，放大页面确认，不要凭文本"（盖章）"认定。
- 专用章名称各机构不同，含"检验检测专用章""检测专用章"可接受；"公章"不等同专用章。
- 骑缝章残片必须与相邻页能拼合；每页一个完整小章不算骑缝章。
- 报告附件的骑缝要求按机构规定，至少检查正文。
- Word 无法渲染时，可用包结构证据（无 drawing/pict、无图片关系、全文无印章字样）证明"无印章"，但必须在报告中说明未做视觉复核；不得仅凭"没有提取到图片"下结论。
- `referenced=false` 的页眉/页脚/图片不会被 Word 渲染，不能作为印章证据。

## R04 主编号前后缀规则（B · 主要）

**不通过条件**：同批主编号前后缀未 100% 统一，例如部分带 A、部分不带 A。

**取证位置**：同批全部报告的封面、页眉、页脚、结论页、文件命名。

**判定步骤**：

1. 收集本次提供的同批报告；未提供完整批次时说明比对范围，不得因缺少其他文件直接判规则失败。
2. 提取每份报告的主编号（不是报告编号），原样抄录。
3. 分解为主编号前缀 + 流水号 + 后缀（字母、分隔符、版本号）。
4. 逐位比对：后缀有无、字母大小写、连字符、空格、位数、补零。
5. 统计不一致项，列出每份文件的编号与差异。

**通过**：同批主编号前后缀完全统一。

**不适用**：单份报告审核、未做同批比对时记"不适用"，并在覆盖表说明"未提供同批文件"；用户明确要求同批审核但文件不全时标“待复核”，并列明缺少的文件。

**不通过示例**：

- 8 份中 6 份为 `JC2026-001`，2 份为 `JC2026-001A`；
- 同批部分用 `-01`，部分用 `_01`；
- 流水号有的 3 位、有的 4 位。

**易错点**：

- 只有一份报告且用户未要求同批比对时，记"不适用"并说明原因，不要判通过；用户要求同批审核却缺文件时标“待复核”，并列明缺少的文件。
- 主编号与报告编号、样品编号可能不同，先确认字段含义。
- 精确字符串比对；全角/半角、大小写差异也算不一致。
- 同批定义以用户提供的清单/批次号为准；报告内无批次信息时要求补充。

## R05 报告编号唯一性（A · 严重）

**不通过条件**：同一份报告内出现不一致的报告编号。

**取证位置**：封面、页眉/页脚、声明页、结论页、附件、骑缝边、电子文件属性。

**判定步骤**：

1. 全文搜索"报告编号""No.""编号"等字段，收集所有出现位置。
2. 同时检查页眉/页脚滚动的编号、结论表标题编号、附件引用编号。
3. 原样抄录后精确比对，包括年份、分隔符、空格、后缀。
4. 检查是否有模板残留的旧编号或另一份报告的编号。

**通过**：全文报告编号完全一致。

**不通过示例**：

- 封面 `JC-2026-1234567`，页眉 `JC-2026-1234568`；
- 结论页沿用模板编号 `JC-2025-7654321`；
- 正文编号带 `A`，封面不带。

**易错点**：

- 报告编号与样品编号、委托单号容易混淆，先按字段名定位，再看格式。
- 只差一位数字也必须报；不要因"看起来像"放过。
- 一个编号出现在图片/印章中时，放大核对。

## R06 报告编号与样品编号关联（A · 严重）

**不通过条件**：报告编号中的 7 位数字与样品编号前 7 位数字不一致。

**取证位置**：封面报告编号、样品信息表/委托信息表中的样品编号。

**判定步骤**：

1. 按报告编号结构定位其中的 7 位连续数字（常见为年份后的流水段）。
2. 取样品编号的前 7 位字符（样品编号常带前缀/后缀，如 `1234567-01`、`S1234567`）。
3. 逐字符比对，含前导零；不要补零、截断或四舍五入。
4. 多样品报告：每个样品编号分别与报告编号核对，并检查样品与项目的对应关系。

**通过**：报告编号 7 位数字 = 样品编号前 7 位。

**不通过示例**：

- 报告编号 `JC-2026-1234567`，样品编号 `1234568-01`；
- 报告编号中取到 `2026123`（取错段），实际关联段为 `1234567`。

**易错点**：

- 报告编号含多个 7 位数字时，按编号结构确定关联段；拿不准时标“待复核”，不得猜测关联段。
- 样品编号前 7 位含字母时，规则按"前 7 位数字"理解，需与用户确认编号规则。
- 样品编号不足 7 位或编号结构不明时无法完成比对，标“待复核”；不能据此判定数字不一致。
- 样品编号字段完全缺失时记录结构性缺失并标“待复核”；R06 仅在可比对的 7 位数字确实不一致时判不通过。
- 样品编号带 `-01`、`/A` 等后缀不影响前 7 位比对。
- 多页样品表分页时，确认没有把不同样品的编号串行。

## R07 标准号（含年份）有效性（B · 主要）

**不通过条件**：同一标准的年代号写法不一致，或标准缺年代号。

**取证位置**：封面"检测依据"、方法表、结论汇总表、页眉、附件、原始记录引用。

**判定步骤**：

1. 收集全文所有标准号出现处，原样抄录（如 `GB/T 1234-2020`、`GB/T 1234—2020`、`GB/T 1234`）。
2. 按标准号主体分组（忽略年份和连接符差异），比对同一标准的年份。
3. 仅按 JSON 条件核对标准年代号是否缺失或同一标准写法是否不一致；不得额外强制四位年份，也不得把客户要求、目录或标准名称当作已提供标准正文。
4. 检查标准号主体是否一致（如 `GB/T` 与 `GB`、编号数字）——主体不一致说明可能引用了不同标准，作为"补充观察"要求核实，不单独据此判 R07 不通过。
5. 标准已被替代/废止、年份未来等，作为"补充观察"提示复核，不擅自升级等级。
6. 报告完全未引用任何标准或未提供标准正文，不自动构成 R07 不通过；只有原文证据满足 JSON 所列“同一标准年代号写法不一致，或标准缺年代号”时才判不通过。

**通过**：同一标准全文写法一致，且均含年份。

**不通过示例**：

- 封面 `GB/T 1234-2020`，方法表 `GB/T 1234-2019`；
- 结论表只写 `GB/T 1234`，无年代号；
- 同一标准一处 `GB/T 1234—2020`（长破折号），一处 `GB/T 1234-2020`——年代号一致，仅连接符差异，记录为写法不统一。

**易错点**：

- 不同标准有相似编号时，先确认标准名称，避免误合并。
- 只按报告实际写法判断年代号是否存在及是否前后一致，不额外规定年代位数。标准正文未提供时，不推定报告违反未提供的条款或限值。
- 标准号出现在表格图片中时，放大核对。
- 不要在无依据时判"标准过期"为 B/A；规则只约束写法一致性与年份完整性。

## R08 方法条件与照片一致（B · 主要）

**不通过条件**：检测方法描述中的温度、电压值与检测照片显示值不一致（逐项检查）。

**取证位置**：方法/步骤描述段落、检测照片中的设备面板、温湿度计、电源显示、环境监控截图。

**判定步骤**：

1. 从方法描述中列出每个项目的关键条件：温度、电压、时间、湿度等（本规则重点温度、电压）。
2. 为每个项目找到对应检测照片，读取照片中仪表/面板显示值，记录页码和数值。
3. 逐项比对描述值与照片值，注意单位（℃/℉、V/kV、AC/DC）和允差。
4. 方法给出允差范围时，按范围判断；未给范围时按数值是否一致判断。
5. 照片缺失、模糊或读不出数值时标“待复核”；只有照片可核实显示值与方法描述值不一致时，才按 R08 判不通过。

**通过**：所有项目的温度、电压描述值与照片显示值一致（或在方法允差内）。

**不通过示例**：

- 方法写"试验温度 25±2℃"，照片温控箱显示 30.5℃；
- 方法写"试验电压 10kV"，照片电源面板显示 12kV；
- 方法写"60℃±1℃"，照片显示 58℃（超出允差）。

**易错点**：

- 环境温湿度照片不能替代样品/设备条件照片。
- 多张照片对应多个项目时，按项目逐一配对，不要拿 A 项目照片证明 B 项目。
- 照片上的时间戳与检测日期冲突，可作为补充观察或转 R13 核查。
- 设备显示值与设定值不同（设定 25℃、显示 30℃）时，以实际显示值为准并说明。

## R09 评判要求完整性（B · 主要）

**不通过条件**：同一维度、同一口径下，适用要求项与对应数据表结果记录不一致且存在缺项（JSON 所述要求项数与数据行数不一致）。

> 数量只有在要求项与结果数据行处于相同对象/条件维度时才可比较；不同维度的主题数与样品行数不直接比较。

**取证位置**：判定依据/技术要求条款、数据表、结论汇总表。

**判定步骤**：

1. 从判定依据中逐项列出适用要求及其对象/参数/条件，按语义确定应有的结果记录。
2. 将要求与数据表中的结果按同一维度逐项映射；不以要求主题数直接对比样品行数、记录行数或参数数。
3. 允许同一单元格合并表述多个要求结果，或结果记录未重复使用要求中的标签；只要原文语义和数据证据足以确认对应关系，就视为已覆盖。
4. 合并跨页续表、检查合并单元格及字段布局，避免漏读或重复计数。
5. 只有在同一维度、同一口径下确认要求项无对应结果记录/证据，或按 JSON 定义存在要求项数与对应数据行数不一致时，才按 R09 判不通过；单纯原始数量不同但语义映射完整，不构成缺项。
6. 要求项或结果记录缺失、无法确认对应关系时，按证据限制标“待复核”；有充分证据确认具体要求未记录/未覆盖时，仍按 R09 判不通过。

**通过**：每个适用要求项都能对应到同维度的结果记录/证据；无需机械要求要求项数与原始数据行数相等。

**不通过示例**：

- 同一项目/样品维度明确要求 5 项（外观、尺寸、电压、绝缘、温升），对应数据记录仅覆盖 4 项，缺"温升"；
- 同一维度明确要求 3 项，对应结果记录仅覆盖 2 项。

**易错点**：

- 按语义关联要求与结果；不同标签不等于未执行，同一记录可对应多个要求项。仅在相同维度确认缺少对应结果时判缺项。
- 跨页表格续表要合并计数。
- 数据表有行但数值为“/”或空白时，只有在规则明确要求该项数据且可确认对应记录缺失时，才作为 R09 缺项；不能由空值推定 R10 越限或 R12 错误合格。
- 结论表列了项目但正文无数据时，先确认规则要求及数据表覆盖；无法确证是否缺项时标“待复核”。

## R10 极限值代入验证（A · 严重）

**不通过条件**：最大值大于上限，或最小值小于下限（实测值超出规定区间）。

**取证位置**：数据表每项目实测值、技术要求上下限、判定列。

**判定步骤**：

1. 抄录每个项目的全部实测值、上限、下限及单位；多组/多列分别计算。
2. 由审核 LLM 逐值核对 `max`、`min` 与限值，遵循报告明确引用的判据和舍入规则；不得在判据未说明时自行假设边界是否包含。仅在证据满足 JSON 的超限条件时判 R10 不通过。本地代码不计算或作出此项审核判定。
3. 注意负值、科学计数法、单位换算（mA/A、kV/V）、修约规则。
4. 检查判定列是否与计算结果一致；不一致时同时触发 R12。
5. 审核时由 LLM 对全部读数逐值核对限值并确认可识别的极值。最终报告说明测量组页码和覆盖范围，并提供足以复核结论的读数、限值、行列归属与来源依据；完整列出所有异常和不确定项，不设引用长度或发现数量上限。

**通过**：全部可核实读数满足报告明确适用的判据及舍入规则；判据或端点含义不明确时标“待复核”，不自行推定。

**不通过示例**：

- 要求 ≤ 15.0，实测最大 15.2；
- 要求 ≥ 10.0，实测最小 9.8；
- 要求 -40℃~-10℃，实测 -8℃（高于上限）；
- 要求 10~15，实测含 9.99（未按修约值时按原始值判断，需说明）。

**易错点**：

- `<LOD`、`未检出`、`ND` 等非数值：按方法规定处理（通常不参与极值比较），并在报告中说明处理方式。
- 混合单位先统一再比较；温度负号不要漏。
- 多子项（如 3 个样品 × 5 次）必须全部纳入极值。
- 按适用文件明确规定的修约方式与端点符号处理边界值；未说明时不自行默认严格或包含边界，必要时标“待复核”。

## R11 结论一致性（A · 严重）

**不通过条件**："结论汇总 & 试验项目信息"中的"结果评判"与正文同一检测项目的评判结论不一致。

**取证位置**："结论汇总"表、"试验项目信息"表、正文各项目结论段、结论页。

**判定步骤**：

1. 建立"项目 → 正文结论"映射，逐项抄录。
2. 建立"项目 → 汇总表结果评判"映射。
3. 逐项比对，先归一近义词：合格=符合=通过；不合格=不符合=不通过。
4. 对名称/编号错位先依方法、参数等实际证据确认是否为同一项目；名称或编号错位本身单独记录并确认关联，不直接判 R11。
5. 发现不一致时，同时确认哪一处与数据相符，便于整改。

**通过**：同一项目在正文与汇总表中的结论完全一致。

只有已确认对应同一项目、且正文结论与汇总表结果评判相反，才满足 R11。缺少一侧或无法确认项目关联时标“待复核”；不得仅因无法比对判不通过。

**不通过示例**：

- 正文"绝缘电阻：合格"，汇总表"结果评判：不合格"；
- 正文"尺寸偏差：不符合"，汇总表写"符合"；
- 汇总表漏掉正文中的不合格项目。

**易错点**：

- 分项结论与综合结论不同是正常的；本规则只比对**同一项目**。
- "合格"与"符合"可视为一致；"基本合格"等模糊表述单独标注。
- 项目名称不同但指向同一检测内容时，按检测方法/参数确认后再比对。
- 汇总表采用图片时，放大逐格核对。

## R12 结论与数据逻辑（A · 严重）

**不通过条件**：存在未达标数据仍判"合格"。

**取证位置**：结论页、结论汇总表、数据表判定列、技术要求。

**判定步骤**：

1. 对每个判"合格/符合"的项目，逐参数复算是否满足要求（不只看极值，含外观、数量、时间等非数值项）。
2. 对判"不合格"的项目，确认综合结论是否如实反映。
3. 检查单项否决项：任一关键项不合格时，综合结论不应为"合格"。
4. 检查"合格"是否基于错误的限值、漏检项目或空数据。
5. 与 R10 联动：R10 判越界、R12 判结论逻辑；同一证据分别记录并标注关联。

**通过**：所有"合格"结论均有达标数据支撑。

**不通过示例**：

- 数据表有 1 项超上限，判定列仍写"合格"，综合结论"合格"；
- 外观检查记录"有划痕，不符合"，综合结论仍"合格"；
- 5 项要求只测 4 项，结论仍"合格"。

**易错点**：

- 仅凭报告写"合格"不能反推数据合格，必须逐项复算。
- 按适用要求明确给出的比较符号和舍入规则判断边界；未明确时不得自行假设端点包含。
- "复检合格"需确认复检数据本身达标，且报告说明了复检原因。
- 综合结论用"所检项目合格"时，注意其范围是否排除了不合格项。

## R13 日期链递增（A · 严重）

**不通过条件**：生产日期/批次号、来样、检测、签发日期不满足递增链。

**取证位置**：样品信息表（生产日期、批号）、委托/来样记录、检测记录（起止日期）、签发/批准页。

**判定步骤**：

1. 提取全部关键日期：生产日期、批号（可解码时）、来样/收样日期、检测起止日期、报告签发日期。
2. 统一日期格式（`2026/3/1`、`2026-03-01`、`2026年3月1日`）后排序。
3. 校验 `生产 ≤ 来样 ≤ 检测开始 ≤ 检测结束 ≤ 签发`；任一逆序即不通过。
4. 批号能解码出生产日期时，与生产日期比对。
5. 日期缺失或批号无法解码时，记录证据限制并标“待复核”；仅当已取得的日期证据证明递增链逆序，才按 R13 判不通过。签署日期缺失按 R02 条件另行判断。

**通过**：日期链单调不减，批号与生产日期一致（可解码时）。

**不通过示例**：

- 来样日期 2026-03-05，检测日期 2026-03-01；
- 签发日期 2026-03-08，检测结束 2026-03-10；
- 生产日期 2026-04-01，来样 2026-03-20。

**易错点**：

- 允许同一天（递增链按"不早于"理解），不要把相等判为逆序。
- 检测跨多日时取开始和结束分别校验。
- 批号不等于日期，只有能依据明确规则解码时才比对；无法解码不证明日期逆序，应标“待复核”。
- 时区、跨年、闰日由审核 LLM 依据真实日历核对，说明日期来源和关系；本地代码不作日期审核。

## R14 检测日期在设备有效期内（A · 严重）

**不通过条件**：任一检测项目的检测日期超出参与设备的使用有效期。

**取证位置**：设备一览表（设备名称、编号、使用有效期）、检测记录中的设备使用记录、方法表。

**判定步骤**：

1. 列出每个检测项目实际使用的设备及设备编号。
2. 从设备表/台账取每台设备的**使用有效期**（不是校准有效期）。
3. 取该项目检测日期（跨多日时取每一天/起止）。
4. 比对：检测日期 > 使用有效期截止日 → 不通过；截止日当天有效。
5. 设备表未载明使用有效期时，不能据此证明检测日期超出使用有效期；将字段缺失/无法核验标为“待复核”，不据此判 R14 不通过。

**通过**：所有参与设备的检测日期均不晚于使用有效期。

**不通过示例**：

- 设备使用有效期至 2026-03-31，检测日期 2026-04-02；


**易错点**：

- 使用有效期与校准有效期是两个字段，不要混用。
- 设备表只有购置日期、无有效期，不能推算超期；记录为待核实，不判 R14 不通过。
- 设备与项目的对应关系需从原始记录确认，不能按设备名称猜。
- 一台设备参与多个项目时，逐项目核对日期。

---

## R15 检测日期在校准有效期内（A · 严重）

**不通过条件**：任一检测日期落在设备校准有效期之外。

**取证位置**：设备表（校准日期、校准周期、有效期至、证书编号）、校准证书、检测记录。

**判定步骤**：

1. 列出每个项目使用的设备及校准信息。
2. 由审核 LLM 确定校准有效期：直接读取"有效期至"；仅有校准日期+周期时，依据明确提供的周期核对到期日并说明依据；信息不足时不得猜测。本地代码不作到期日判定。
3. 已知适用截止日且检测日晚于该日，足以证明超期，不要求先取得起始日；已知适用起始日且检测日早于该日，也足以证明超期。检测日未晚于截止日而起始日未知时，只能确认未超出已知截止边界，不能宣称完整期间已核实，也不能判已超期。较新的校准日期不能直接替代检测当时适用的起始日。
4. 记录材料中明确的校准状态；状态信息本身不能替代校准有效期起止日期的核对。
5. 缺少起始日、历史证书或其他校准信息时，标“待复核”并说明所能确认的日期边界；只有证据证明检测日期超出校准有效期才按 R15 判不通过。

**通过**：所有检测日期均落在对应设备的校准有效期内。

**不通过示例**：

- 校准有效期至 2026-02-28，检测日期 2026-03-03；
- 有证据明确校准有效期起始日为 2026-03-10，检测日期为 2026-03-08；
- 校准周期 12 个月，校准日期 2025-03-15，检测日期 2026-03-20。

**易错点**：

- 校准有效期截止日当天有效。
- 周期推算按证书约定的月/年，不按 365 天简单相加。
- 设备表有多行同型号设备时，按设备编号精确对应。
- “检定”与“校准”证书都按其明确有效期核对；不得仅凭状态或较新的校准日期推定检测日期超期。

## R16 分包/认可状态声明（B · 主要）

**不通过条件**：分包声明既非"无"，也未注明分包实验室机构名称。

**取证位置**：报告声明页、报告说明、资质/认可页、结论页脚注。

**判定步骤**：

1. 找到分包声明条款，原文抄录。
2. 若声明为"无分包"/"本报告无分包" → 通过。
3. 若声明为"有分包/部分分包"，检查是否注明分包实验室的**机构名称**（全称）。
4. 检查分包项目是否在报告中标注、分包结果是否注明来源。
5. 认可状态声明（CMA/CNAS）缺失或表述矛盾，作为补充观察；本规则只按分包条件判定。

**通过**：分包声明为"无"，或明确列出分包实验室名称。

**不通过示例**：

- "本报告部分项目由分包实验室完成"，未写机构名称；
- "部分分包"但只写"外部实验室"；
- 声明写"无"，但正文标注某项目为分包——记录矛盾并要求核实。

**易错点**：

- "无"必须是明确表述；空白/未提及不算"无"，按声明缺失处理。
- 整份报告完全未提及分包 → 视为"既非无、也未注明分包实验室"，判不通过（B），不要判"不适用"。
- 分包实验室名称需为可识别全称，简称/代号不足。
- 认可状态声明与分包声明是两件事，不要互相替代。
- 分包项目的结果判定责任归属可作为补充观察。

## R17 中文错别字（C · 次要）

**不通过条件**：存在错别字，或语句不通顺、不完整。

**取证位置**：全文（封面、正文、表格、结论、声明、页眉页脚）。

**判定步骤**：

1. 通读全文，标记高置信错别字、别字、漏字、重复字。
2. 标记病句、成分残缺、语义矛盾、标点导致的断句错误。
3. 每条给出：页码、原文、问题类型、建议改法。
4. 同一错字多处出现可合并为一条，列出所有页码。
5. 专业术语、化学名、仪器名、标准名、人名、单位符号不作为错别字；不确定时标"疑似"。

**通过**：无错别字，语句通顺完整。

**不通过示例**：

- "试验结果均复合要求" → "符合"；
- "检测依据为 GB/T 1234-2020 进行检测" → 句式杂糅；

**易错点**：

- 不要全文改写；只列问题与建议。
- 报告中的行业简写（如"委外""送样"）不是错别字。
- 数字与单位、英文缩写、上下标不按错别字处理。
- 疑似项单独列出，避免误报；同一处多个问题合并。
- 全文没有任何中文内容（纯英文报告）→ 不适用，并在覆盖表注明；不要写成"通过"。

## R18 英文语法（C · 次要）

**不通过条件**：英文单词拼写或语法错误，或句子不完整。

**取证位置**：英文摘要、英文项目名称、英文结论、图注/表注、单位与机构英文名、证书英文页。

**判定步骤**：

1. 逐句检查拼写、单复数、时态、冠词、介词、主谓一致。
2. 检查句子是否完整（缺主语/谓语、断句）。
3. 检查英文项目名称与中文是否对应，术语是否统一。
4. 每条给出页码、原文、问题、建议改写。
5. 标准英文名、商标、缩写、机构官方英文名不判错；大小写/格式问题作为建议。

**通过**：英文拼写与语法正确，句子完整。

**不通过示例**：

- "Test result is comply with the requirement."（语法错误）；
- "The sample were tested..."（主谓不一致）；
- "Test method: GB/T 1234-2020." 作为句子不完整（图注可接受，需看语境）。

**易错点**：

- 中式表达但语法正确，不判错。
- 全大写标题、缩写、化学式不按拼写错误处理。
- 同一术语多种译法属于一致性问题，可作补充观察。
- 只报高置信错误，避免把专有名词误判。
- 全文没有任何英文内容 → 不适用，并在覆盖表注明；不要写成"通过"。

## R19 照片 AI 生成标记（B · 主要）

**不通过条件**：照片出现 AI 生成类水印或生成痕迹。

**取证位置**：报告内所有检测照片、样品照片、设备照片、附件图片；含 Word 内嵌图与 PDF 图片。

**判定步骤**：

1. 逐张查看照片，检查水印/角标：`AI生成`、`AI generated`、`DALL·E`、`Midjourney`、`Stable Diffusion`、`文心一格` 等。
2. 检查生成痕迹：文字/仪表数字扭曲、指针与刻度不符、手指/线缆异常、光影方向矛盾、重复纹理、边缘融合、反射不自然。
3. 检查图片元数据（如可提取）：`Software`、`CreatorTool`、生成工具标签；元数据缺失本身不判不通过。
4. 检查照片与检测项目、设备、日期是否自洽（如仪表读数与 R08 条件冲突）。
5. 发现明确水印或高置信生成痕迹 → 不通过；仅低分辨率/压缩模糊且无法判断时标“待复核”，不得据此判不通过。

**通过**：所有照片无 AI 水印、无明显生成痕迹。

**不通过示例**：

- 照片右下角有"AI生成"水印；
- 设备面板数字排列错乱、指针指向与数值不符；
- 多张照片人物手指数量异常/背景重复。

**易错点**：

- "AI"可能是设备型号、软件名、公司缩写，结合上下文判断。
- 手机美颜、HDR、夜景增强不属于 AI 生成。
- 拍摄屏幕产生的摩尔纹、压缩噪点不是生成痕迹。
- 拼接/PS 痕迹可作为补充观察；规则判定以"AI 生成类水印或生成痕迹"为准。
- 全篇没有任何照片 → 不适用；若检测方法要求照片而报告缺失，作为证据缺失写入"结构性缺失/补充观察"，不按 AI 标记判不通过。

## 规则联动与去重

| 组合 | 场景 | 处理 |
| --- | --- | --- |
| R10 + R12 | 数据越界且结论仍合格 | 两条都记，标注"关联问题"；总评按 A |
| R05 + R06 | 报告编号不一致导致 7 位比对失败 | 先按 R05 记录，再按 R06 核对可确定的编号 |
| R02 + R13 | 签署日期缺失/逆序 | R02 记签署不齐，R13 记日期链；分别说明 |
| R09 + R12 | 要求项缺失但结论合格 | 分别记录：缺项（B）与结论逻辑（A） |
| R07 + R08 | 标准年份错误且方法条件不符 | 独立记录，不互相替代 |
| R14 + R15 | 设备超使用期且超校准期 | 两条都记，分别列设备与日期证据 |

统计口径：问题条数按"规则 × 位置"计；同一证据触发多条规则时在统计备注中说明关联，避免读者误以为缺陷数量翻倍。
