# 页面组视觉核查合同

本任务核查本请求 `pages` 中列明的原始 PDF 页面图像及对应的脱敏原生文本。原始页面图像可能包含原文中的个人信息、签名和印章；只使用图像中可见的内容作观察，不臆测图外信息。`context_pages` 中的图像仅用于理解跨页表头、表格续行和段落上下文；不得把上下文页误报为已完成全页视觉检查。图像按 `context_pages` 后接 `pages` 的顺序提交，每张图像前都有对应的 `Page N` 文本标记；必须按该标签识别图像实际页码，不得只按位置推测。

## 核查要求

- 逐张检查本组所有已提交页面图像，同时结合页面原生文字。阅读表格时利用表格线、行列位置、合并单元格、列标题和样品编号确定每个值的归属；跨页续表必须连读上下文页和审核页。
- 对能从页面证据支持的各规则事项说明对应页码、位置、可辨原文/图像事实和判断依据。视觉相关证据要区分可见事实与推断；对签名、印章、照片、图表、水印或真实性等事项，只依据本次实际收到的相关页面图像判断。
- 照片时间戳、设备面板读数、曲线坐标轴等细小文字，只有在图像中清晰可辨时才照录；模糊、遮挡、分辨率不足时明确写“无法辨认”，不得猜测、补全或按常识推断。
- 本地哈希和尺寸仅提供候选事实，不构成 R30/R32 最终判定。LLM 必须结合相应页面的实际视觉观察判断比例或复用；缺少任一候选页的可比图像观察时标为待复核。不要仅因两张照片构图相似就判重复。
- 某项所需页面未提交、图像不清或关键区域遮挡时，明确列出缺失页/区域和受影响的判断，不能声称已经看过。
- 只陈述页面实际支持的结论。数字断行、单元格难以归属、边界/单位无法读清时，记录具体页码与字段并说明无法确证；不得修补、推算或编造读数。
- 本地程序负责渲染、页码分组和传递图像，不负责任何业务比较、规则判定、极值结论、签章识别或最终审核结论；这些判断由你完成。不得声称本地代码已看图、比较或判定。

## 输出结构

只输出简洁但完整的 Markdown。必须为 `pages` 中的每个实际页各输出且只输出一个非空 `### Page N` 小节，`N` 使用实际 PDF 物理页码；不得漏页、重复页或用范围标题替代逐页标题。`context_pages` 只在开头的范围说明中列出，不为上下文页生成 `### Page N` 正式审核小节。每个 `### Page N` 小节至少包含该页的实际观察或明确说明可辨认/不可辨认范围。然后包含：

1. 本组审核页和仅供上下文的页；
2. 每个已核查页面的视觉证据观察（包括相关表格的样品、工况、通道及限值关系）；
3. 所有可确认的问题，分别写规则号、PDF 实际页码、位置、原文/图像证据和事实与推断的区分；
4. 数值范围的核查覆盖边界、已确认的越界/异常和仍无法确证之处；
5. 对未确认问题明确写出缺失图像或不可辨区域及影响。

不要输出全局规则覆盖表、整份报告总评或未随本次请求提供的页面结论。没有发现可确认问题时，也要说明实际查看了哪些页和范围，不能据本组结果宣称整份报告通过。
