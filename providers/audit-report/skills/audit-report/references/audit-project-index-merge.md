# 分段扫描合并为完整项目目录合同

你只负责把已校验的多个报告分段扫描合并为完整全局目录，不做业务审核。输入中的每个分段都已包含其全部正式页。`reviewed_pages` 是可省略的历史兼容元数据；若存在，不将其作为覆盖证明。`segments` 与 `non_project_pages` 可能省略；本地结构校验按空数组处理，并验证其分类范围共同覆盖全部正式页。

- 依据各段 `id`、`title`、`page_start`、`page_end`、新项目起点原文锚点和相邻页范围，合并同一项目的跨段范围。`start_status`/`end_status` 等可选状态字段不是权威来源，也不是合并条件。不得把上下文页重复计入，不得遗漏任何扫描记录中的项目。
- 分段中的 `start_evidence`/`end_evidence` 是可选补充信息；如提供，可结合相邻页上下文核实项目边界：新项目从可核实的正文标题/起点开始；上一项目标题之后、下一项目实际正文标题之前，若原生文字中的图注、续表或附件标题可关联到上一项目，应保留在上一项目范围，不能仅因接近下一标题就改归新项目。项目内部或末尾空白/低文字页不自动成为结束或非项目页；结合正式页证据决定，存在疑点时保留在相应项目范围供后续 R01 核查。
- 每个新出现项目 ID 的首段 `start_quote` 是其起始物理页的来源锚点；合并范围时不得把它改指到其他页或省略对应项目。后续分段如沿用此前已知的项目 ID，可不重复提供起点引用；必须保留该 ID，并按其分段页范围连续合并。
- 每个不同项目都必须在输出中恰好出现一次。最终输出 `id` 集合必须保留所有分段扫描中出现的项目标识；跨段续接的同一稳定ID合并为一个目录项。若输入对同一边界或项目标识存在无法调和的冲突，不能静默丢弃；按证据生成最完整的目录并保持各项目标识。
- 输出项目按实际 PDF 物理 `page_start` 从前到后排列；不要按项目编号字符串排序。
- 项目页范围必须是来源分段正式页范围所支持的连续范围，覆盖扫描识别出的项目开始至结束。相邻两个项目可共享一个边界页。仅 `non_project_pages` 中注明的页可不属于任何项目；不得根据未提供的全文推测未出现的项目。
- 报告原文可能重复使用相同可见项目编号。不同独立项目必须保留为不同目录项，并沿用分段扫描分配的稳定、互不重复标识。
- 仅当全部扫描均未识别到项目时，`projects` 才可为空，且需在 `no_projects_reason` 说明原因。`projects` 非空时，`no_projects_reason` 可省略或留空，不能用它表示目录不完整，也不作为目录有效性的附加门槛。

只返回现有全局目录JSON结构：

```json
{"projects":[{"id":"6.1","title":"项目名称","page_start":1,"page_end":32}],"no_projects_reason":""}
```
